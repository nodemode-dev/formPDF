## 1. Versions, never edits in place · _v0.1.0 (services/pdf/docs.py derive, routers/pdf.py _derive)

Every opened PDF becomes a working copy `Pdf/pdf_xxxxxxxxxx.pdf` with a meta file (name, original path, root key, protection). Every operation writes a new id derived from its source, re-applies protection and discards the output on failure; nothing is deleted on success. The window's Undo, the agent's undo and the recents all rely on old versions staying where they are, so do not prune them while a session is open.

## 2. True redaction rasterizes · _v0.1.0 (services/pdf/edit.py redact)

Redaction renders the marked pages with pypdfium2, burns black boxes in and replaces those pages with images, so nothing under a box survives; the UI and the agent guide both say those pages become images. Superseded in 0.5.0 by entry 30; this path remains as `mode: "raster"` for scanned pages.

## 3. Find text in a PDF and redact it · _v0.1.0 (services/pdf/search.py pattern, find, areas; routers/pdf.py find)

Search runs over PDFium's text page, so matches carry real character boxes even across line breaks; each match returns its page, the matched text, trimmed context and one rect per line in top-left page points (the frame the redaction areas already use). Presets are regexes with a check function where a regex alone over-matches: phone numbers need 7 to 15 digits, card numbers pass Luhn, dates accept numeric and month-name forms. Results stop at 2000 matches with `truncated` set. `areas()` pads each rect by a point so redaction covers descenders.

## 4. Headers, footers, Bates numbers and cropping · _v0.1.0 (services/pdf/edit.py header_footer, crop, _content_margins)

Header and footer text is drawn with reportlab on an overlay per page and merged, honouring each page's rotation and view box, with `<<page>>`, `<<pages>>`, `<<date>>`, `<<file>>` and `<<bates>>` tokens, a page range, odd or even pages and a start number. Bates numbers are a prefix plus a zero-padded counter. Crop writes `/CropBox` only, so content outside stays in the file and the crop can be undone; that is why the panel points to Redact for removal. Remove white margins renders each page and finds the content bounds, padded by 4 points.

## 5. PDF comment threads · _v0.1.0 (services/pdf/annot.py _thread, comments; routers/pdf.py get_comments)

Replies are Text annotations with `/IRT` pointing at the parent and the reply flag set, so Acrobat and other readers show them as a thread. Status is a separate hidden Text annotation with `/State` and `/StateModel /Review`, as Acrobat writes it. `comments()` reads both back: replies are followed up their `/IRT` chain to the root comment, and the latest review state per comment wins.

## 6. PDF reflow, Word, forms, sanitising and compare · _v0.1.0 (services/pdf/layout.py, word.py, forms.py, sanitize.py, create.py, compare.py)

Reading order is an XY-cut that prefers vertical gutters and merges bands that share one, so aligned paragraph gaps do not interleave columns; tables and pictures take part in the cut. Words use pdfplumber with `x_tolerance_ratio=0.15` because the 3 pt default glues tight words. Form fields get upright appearance streams with `/Matrix` and `/MK /R` for rotated pages, `NeedAppearances`, Acrobat's AFDate actions for date fields, and radio groups as a parent with widget kids. Sanitising flattens widgets by painting their normal appearance, drops hidden layers by filtering `/OC` marked content, drops text drawn in render mode 3, and prunes orphans so removed data leaves the file. Compare pairs pages by exact text first, then aligns the rest by word-set similarity.

## 7. Lenient MCP protocol versions · _v0.1.0 (routers/mcp.py mcp)

2026-07-28 and 2025-11-25 are advertised, and 2025-06-18, 2025-03-26 and 2024-11-05 are accepted at initialize because older Cursor and Codex builds disconnect otherwise. Clients that send no session id share an "anon-[client name]" key so their turns still group.

## 8. What moved out of formsld and what stayed · _v0.1.0 (app/)

Moved unchanged apart from branding: services/pdf (core, edit, annot, forms, layout, word, sanitize, search, create, compare, docs), routers/pdf.py, the system and media routes, the discovery file, the MCP protocol handling and stdio bridge. Removed: the deck store and ops, compiler, autodraft, intake, templates, pptx reader and writer, lint, exports, the deck routes, `core.to_deck`, `core.images_deck` and the `/to-deck` and `/images-deck` routes. formsld's backend entry 13 (page text in reading order for deck notes) went with to_deck; its insight lives on in layout.py, which already orders words by position.

## 9. A small picture store instead of formsld's media service · _v0.1.0 (services/media.py)

`core.extract_images` needs somewhere to put pictures with stable ids so the window can show them and agents can name them. formsld's media service also handled video, audio, fonts and deck references; formpdf keeps only the image part (sniffing, size probing, content-hash ids, `~/Formpdf/Media`) as its own module, so no import reaches back into a slides codebase.

## 10. PDF to PowerPoint with real text boxes · _v0.1.0 (services/pdf/slides.py to_pptx, _textless, _textbox, _table; routers/pdf.py to_pptx)

One slide per page at the first page's size (PowerPoint allows one slide size per file; clamped to 1 to 56 inches, other pages fitted and centred). The slide picture is the page rendered from a copy whose text-showing operators (Tj, TJ, quote and double quote, keeping their line moves) are stripped, so the words are not doubled under the text boxes; when stripping fails the full render is used. Paragraphs and headings from `layout.page_blocks` become text boxes at their boxes with zero insets, a 3 percent width allowance, wrapping only for multi-line paragraphs, and runs with size, weight, style, colour and font; tables become PowerPoint tables with the No Style, No Grid style and no fills so the page's own rules show through. Known limits: text inside form XObjects and annotation appearances stays in the picture, and rotated words are not placed as boxes.

## 11. Contact sheets for agents · _v0.1.0 (services/pdf/slides.py contact_sheet; routers/pdf.py sheet)

Up to 12 pages in one PNG, one to four columns by count, each labelled "Page N" under it on a dark ground, 1600 px wide by default. One image per call keeps an agent's verification step to one tool result instead of one per page.

## 12. The MCP split: seven tools, one pdf tool with actions · _v0.1.0 (routers/mcp.py TOOLS, t_pdf, _read, _change, _export)

formsld exposed PDF work as one `pdf` tool next to 24 deck tools. formpdf keeps that tool and its action names (so agents and the formsld skills transfer), replaces `to_deck` with `to_pptx`, and adds the workbench's operations as actions; around it sit get_context, open_pdf, render_pages, extract, save and undo. One action-style tool keeps the tool list short for clients that cap tool counts, and the actions split into read, change and export lists that drive consent and output naming.

## 13. Live agent changes land in the window as a turn · _v0.1.0 (routers/mcp.py _source, _land, t_undo; routers/live.py handle doc; services/bridge.py window_doc)

The window reports its open document (id, key, page, unsaved changes, whether the newest state is an agent's) over /api/live whenever its chrome syncs. A change without a path derives a new version from the window's current id and calls the `commit` window tool with the turn id and the agent's name; the window refuses if its document moved on meanwhile. A turn is every mutating call from one session less than 90 s apart. With no window, the engine keeps its own version list per document key in `OPEN` and undo steps back over the newest turn there.

## 14. Consent for every action that writes · _v0.1.0 (routers/mcp.py _mutating, _consent)

A review of formsld 0.5.1 found that only `pdf to_deck` asked for consent while redact, crop, header_footer, merge, split and to_docx wrote files freely. In formpdf every change and export action, open_pdf, save and undo go through `_consent`: the window asks once (120 s), Allow persists `agentsAllowed`, Not now is cached for 120 s. With no window connected (headless, CLI) there is nobody to ask and calls proceed.

## 15. Compress without document info · _v0.1.0 (services/pdf/edit.py compress)

pypdf's `compress_identical_objects(remove_orphans=True)` dereferences the writer's `/Info` and raises AttributeError when there is none, which is the state after Remove hidden information strips metadata. Compress skips the identical-object pass in that case; pictures and streams are still recompressed.

## 16. One action registry for MCP, the CLI, batch and the palette · _v0.2.0 (services/pdf/actions.py; routers/mcp.py READ_ACTIONS to LABEL, _change, _export, _read; routers/pdf.py action_list)

The parity plan adds about forty actions, and each one has to reach the window, the MCP `pdf` tool, `./formpdf run`, Home batch and the command palette. Before this, the action names, labels and output suffixes lived as literals in mcp.py, so every new action meant edits in several places that could drift. `actions.py` is now the one table: name, kind (read, change, export), label, suffix, synonyms for the palette, an output extension, and the fields a batch form shows. mcp.py's names are the registry's live lists and dicts (same objects), so the tool's action enum and consent rules follow registration without rebuilding. The 27 built-in actions keep their hand-written branches in `_change`, `_export` and `_read`; an action registered with a `run` handler (later phases, plug-ins) falls through to it: change and export handlers take `(src, out, *, args, pages, passwords)`, read handlers take `(src, *, args, pages, passwords)` and return text plus data. `batch` is false for read actions and for actions that need per-file choices (merge, fill, annotate, form, organize, unlock). GET /api/pdf/actions serves the catalogue.

## 17. The content interpreter · _v0.2.0 (services/pdf/content/fonts.py FontInfo, parse_cmap; interp.py walk, Interpreter, PageContent.within; streams.py write_page, new_form, replace_form)

True redaction, editing text and pictures already on a page, OCR text placement and tagging all need the same thing: every glyph, picture draw and path tied to the operator that drew it, with its box on the page. pdfplumber finds characters but cannot say which operator made them, so it cannot drive a change. `walk(page, pdf)` parses the page's joined content (pypdf joins a /Contents array, so a piece that ends mid-operator is not a problem) and runs a graphics-state machine: CTM stack, text state (Tc, Tw, Tz, TL, Ts, Tr, font and size), text and line matrices, fill colour and the marked-content stack. Each shown code becomes a `Glyph` with its operator index, its position inside that operator, the code bytes, Unicode text, a box from font descent to ascent through the text rendering matrix, the origin, the advance (with Tc, and Tw only for single-byte code 32) and its MCID or Artifact state. Pictures, inline images, forms, paths, clips and shadings become `Draw`s. Form XObjects are walked in place with their Matrix and own or inherited resources, keyed by `where` (the chain of Do operator indexes), with a depth cap of 8, a cycle guard and a four-million-operator budget that sets `truncated`.

`FontInfo` reads simple fonts (Widths, FirstChar, MissingWidth; base encoding plus Differences; glyph names through the Adobe list, uniXXXX and uXXXX forms, with suffixes like .sc or .v1 stripped and ligature names split on underscores), standard 14 fonts without widths through reportlab's AFM tables (Arial, Times New Roman and Courier New names alias to them), Type0 fonts (W and DW, Identity-H and V, embedded CMaps with codespace and CID ranges; other predefined CMaps are treated as two-byte and flagged `approx`) and Type3 fonts (FontMatrix-scaled widths and box). ToUnicode wins over the encoding. `reverse` and `encode` map text back to codes and refuse a character the font has no glyph for, which is how later phases avoid printing question marks. pypdf's encoding and glyph tables are private modules, imported behind a guard so an upgrade degrades instead of crashing.

Checked against pdfplumber on twelve PDFs (reportlab standard and TrueType subset fonts, matplotlib Type3 and Type42, TeX Type1 with custom encodings, a Word-made math PDF, a browser-made PDF, formpdf's own outputs): every glyph origin and width matched to 0.000 pt, counts matched on every page, and text matched except where the font's own built-in Type1 or CFF encoding is the only source of Unicode (two glyphs in a TeX math font), which is not read yet. Writing every page back from its parsed operations rendered pixel-identical in PDFium and extracted the same text. No PDF in that set was tagged, so the MCID and Artifact paths have not run against a real file yet.

`write_page` replaces a page's content with one new stream; `new_form` and `replace_form` add a changed copy of a form under a new resource name and leave the original for the other pages that share it (the caller renames the Do operand).

## 18. The font kit · _v0.2.0 (services/pdf/fontkit.py font_name, covers, pick, available; app/fonts/; formpdf_engine.py selfcheck)

Text formpdf writes into a PDF (added text, edited paragraphs, OCR layers, Bates and headers later) must embed its font, or accents and non-Latin scripts are lost and extraction breaks. `app/fonts/` ships Inter 4.1, Noto Serif 2.015 and JetBrains Mono 2.304 in regular, bold, italic and bold italic with their OFL texts; `config.fonts_dir()` and the freeze script already pointed there, so the frozen engine carries them and `annot.text_font` now finds Inter instead of a system font. `font_name(family, bold, italic)` registers a family with reportlab on first use, which embeds a subset with a ToUnicode map, so fontTools is not needed yet; if a file is missing it falls back to the matching standard 14 font. `covers` checks a string against the font's character map and `pick` walks the families for one that covers it. No shipped family covers CJK; callers must say so (Beat Acrobat B8) until a CJK font is chosen. Checked: all twelve combinations write Greek, Cyrillic, accented Latin and Polish text that pdfplumber and the content interpreter extract unchanged, every font embedded as a subset. The selfcheck reports the number of font files found.

## 19. Batch jobs · _v0.2.0 (routers/batch.py upload, run, _work, status, download, _target, _nest, _prune)

Home > Batch runs one registered action (`Action.batch`) on many PDFs. Each file goes through `mcp.t_pdf` with `path` and an explicit `out`, the same code path agents and `./formpdf run` use, so batch behaves exactly like a file job: the input never changes. It calls `t_pdf` directly rather than `call_tool`, because the person started it in the window and the agent consent question does not apply. A run is a job in memory (`JOBS`, the newest 20 kept) worked through in an asyncio task kept in `TASKS` so it is not collected; the window polls GET /api/batch/{id} for per-file state, the message and the output paths, and GET /api/batch/{id}/zip zips what was written. Results go to a new folder `Exports/Batch <date time> <action label>`; output names follow the agents' `[stem]-[suffix].pdf` rule, and a second file with the same stem gets ` (2)`. Browser uploads are copied into `Formpdf/Batch/<random>/` because the window has no file paths in a browser; on each upload, copies older than a day are removed unless a running job uses them. Field names with dots from the batch form (`footer.center`, `bates.prefix`) are nested into the objects the actions take. Checked over HTTP: three files with Bates footers numbered ACME-000001 on, a refused non-batch action, a zip of three results, pruning of an old inbox folder.

## 20. Session restore and the network list · _v0.2.0 (services/session.py remember, clear, read; routers/live.py handle doc; routers/system.py get_session, dismiss_session, NETWORK, capabilities)

Every change already lands as an immutable working-copy version (entry 1), so a crash loses only what was never applied; what was missing was knowing which version the window had open. The window already reports its open document over /api/live, so the engine writes it to `~/Formpdf/session.json` as it arrives (id, key, name, page, tab, dirty, pages), at most every two seconds unless the id, tab or dirty state changes. A window that closes its PDF on purpose sends no document after having one, which clears the session; a fresh window's first empty report does not, because it never had one, which is how the file survives a reload or a crash to be read by the next start. GET /api/session returns the document only when its working copy still exists, with `recover` true when it had unsaved changes; POST /api/session/dismiss clears it. The page is approximate: the window reports page moves only alongside other changes.

Beat Acrobat B1 needs the network story in one place. `NETWORK` in system.py lists every connection formpdf could make and its state, served in /api/capabilities: today only the local engine link and the desktop update check, which is off because no update key is configured. Features that add a connection (timestamp servers, AI providers, update checks) append their row here. Capabilities also report the font count.

## 21. One route for registered actions · _v0.3.0 (routers/pdf.py act, MEDIA)

POST /api/pdf/{id}/act/{name} runs any registered action that has a `run` handler on a working copy: a change derives a new version through `_derive` (so protection is re-applied and failures discard the output, entry 1), a read returns its text and data as JSON, an export runs into a temporary file with the action's extension and streams it back with a filename (a handler may name the file by returning `filename`). New tools therefore need no route of their own: the window calls the same handler the MCP tool, the CLI and Batch call.

## 22. Links · _v0.3.0 (services/pdf/links.py target, read, change, URL; services/pdf/frame.py; routers/mcp.py _detail)

`edit_links` adds Link annotations from boxes (points from the top left of the unrotated page, the frame redaction areas use; `frame.py` converts both ways through the view box), removes links by page and index as `links` lists them, and with `auto` links every web and email address in the text: the URL pattern runs through `search.find`, so matches carry PDFium's per-line boxes and a URL broken over two lines becomes two link boxes with one target. Boxes that overlap an existing or just-added link are skipped, so running it twice adds nothing. A target is a page number (a GoTo destination with Fit), an email address (mailto:), or a web address (www. and bare domains get https://); anything else, including `javascript:`, is refused, and non-ASCII URLs must use punycode because URI actions are 7-bit. Links are printable, invert on click, and borderless unless `border` asks for a thin blue one. `links` reads URI actions and page destinations (explicit, named, or GoTo) back as page numbers. The change result says `added` and `deleted`; `deleted`, not `removed`, because `_detail` already reads `removed` as sanitize's list of categories.

## 23. Attached files · _v0.3.0 (services/pdf/attach.py change, read, listing, get_file, _tree, _filespec, _pin_ap; routers/pdf.py attachment)

Document-level files live in the catalog's EmbeddedFiles name tree. pypdf can add to it but not remove from it, so `change` flattens the tree (Names arrays and Kids, depth-capped), drops removed names, appends new files and writes one flat Names array sorted by name, which every reader accepts. A file whose name is taken becomes `name (2).ext` rather than replacing the first. Each file is a Filespec with F and UF names, an optional Desc, and an EmbeddedFile stream (Flate-compressed, MIME subtype, Size and ModDate in Params). A file with a page becomes a FileAttachment annotation (a pin) with a 20 point paperclip appearance of its own, because readers otherwise draw it differently or not at all. Files arrive as base64 (the window) or as a path (agents and the CLI), at most 200 MB each. `attachments` lists both kinds and, with `save`, writes one to a path or the Exports folder; the window downloads through GET /api/pdf/{id}/attachment by name, or by page and index for pins. Sanitize keeps its own removal path (entry 6).

## 24. Bates numbers across files · _v0.3.0 (routers/batch.py _work, _bates, _bates_text, _numbered; services/pdf/actions.py header_footer fields)

Acrobat's Bates numbering is a set operation: legal documents are numbered as one run. Batch with Add header and footer and Add Bates numbers now passes each file a start number that continues from the previous file, counting only the pages that file actually numbered (its page range and odd or even setting, the same sequence header_footer counts), and writes `Bates numbers.csv` (file, numbered copy, first, last) into the results folder and the zip. Each row's `note` shows its range. The form's `bates.on` and `bates.across` are batch-only switches and are removed before the call. `bates.on` also fixes a 0.2.0 fault: the batch form always sent start and digits, and header_footer treats any `bates` object as a request for Bates numbers, so every batch header and footer run was stamped with them.

## 25. Measurements · _v0.3.0 (services/pdf/measure.py change, read, snap, value, _annot, _appearance, _measure_dict; services/pdf/content/interp.py Draw.points)

Measurements are written the way Acrobat writes them, so other readers show and re-read them: a distance is a Line annotation with IT LineDimension, open arrows on both ends and Cap; a perimeter a PolyLine with PolyLineDimension; an area a Polygon with PolygonDimension. Each carries a rectilinear Measure dictionary whose X number format holds the unit and the scale (units per point), so the value can be recomputed later and recalibrating never changes earlier readings, plus Contents with the formatted value (optionally after a label). Each gets its own appearance stream (the line or outline in the colour, a 12 percent fill for areas through an ExtGState, the value in Helvetica on a white plate) because readers otherwise draw measurement annotations inconsistently. Values: length times scale, area times scale squared; perimeter sums the segments. `measurements` reads both formpdf's and other tools' measurement annotations back with their value from the stored scale; `measure` removes by page and index in that order.

`snap_points` walks the page with the content interpreter and returns path vertices, segment midpoints and segment crossings in top-left page points, capped at 4000 points and 700 segments for the crossing pass. That needed the interpreter to keep subpaths apart: `Draw.points` now holds each painted path's subpaths (m starts one, re adds a closed one, h closes, curves contribute their end point), so a midpoint or crossing is never invented between two separate shapes. The no-op write-back check stayed pixel-identical on all twelve corpus PDFs after the change.

## 26. HTML, RTF and Excel exports · _v0.3.0 (services/pdf/exports.py document, _items, to_html, to_rtf, to_xlsx, _cell_value, _put; services/pdf/layout.py list_item, strip_runs, running, is_running; routers/pdf.py act)

## 28. Spelling · _v0.3.0 (services/pdf/spell.py Dictionary, check, read, change, _swap, _freetext_ap; core/config.py dict_dir; routers/system.py settings and capabilities; app/dict/en_US)

The dictionary is SCOWL's en_US Hunspell pair (size 60), shipped verbatim with its README, which carries the SCOWL, Ispell BSD and WordNet notices. pyspellchecker was rejected because its English frequency list comes from a subtitle corpus with no clear licence. The reader is formpdf's own and covers the part of the Hunspell format these dictionaries use: SET UTF-8, TRY, REP, NOSUGGEST, ONLYINCOMPOUND, FORBIDDENWORD, FLAG char, long or num, and PFX and SFX rules with strip, add and condition, including the prefix-suffix cross product. It expands every stem into its forms once per language (about 124,000 forms for en_US in a third of a second) and keeps them in memory. Compound rules are not implemented; they only cover ordinals, and any token with a digit is skipped anyway. More languages are Hunspell pairs dropped into Formpdf/dictionaries/<code>/<code>.dic and .aff.

A word passes when it is in the dictionary as written, when it is capitalised and its lower-case form is (sentence starts), when it is all capitals and any form is, or with a trailing 's when its stem is. Skipped: tokens with digits or underscores, words in all capitals (acronyms, on by default), mixed-case words such as iPhone, web and email addresses and file names, and the person's own words (settings `dictionary`) and the call's `ignore` list. Suggestions come from REP pairs, every single edit (deletions, transpositions, replacements and insertions over the TRY letters) and splits into two words, then two edits when fewer than six are close; each candidate gets a cost (a transposition, a doubled or dropped double letter or a vowel swap is cheap), plus a penalty for a capitalised proper noun when the word was lower case and for a different first letter, so "teh" offers "the" first and "thier" offers "their". Two-edit search runs for the first 40 distinct words of a check.

`spell` checks `texts` the caller sends (the window sends comments not applied yet and form field values as typed), plus PDF comments, form text fields and page text by `scope`, and returns each issue with where it is, its offset, a context line and suggestions. `spell_fix` takes fixes by comment (page, index, NM) or field name, applies them from the end of each text so offsets hold, falls back to the nearest whole-word match when the text moved, rewrites a FreeText appearance with formpdf's own text drawing (keeping the size and colour from DA and the fill from IC) so the page shows the corrected text, and fills fields through fill_fields. Settings take `spellLang` and `dictionary` (at most 5000 words of 64 characters); `capabilities` lists the installed languages.

## 29. Page items: text and pictures that stay editable · _v0.4.0 (services/pdf/items.py; routers/pdf.py items_under; routers/system.py font_file)

An item is a Form XObject named `/FpI_<id>` in the page's XObject resources plus one small content stream in the page's `/Contents` array that places it (`q <matrix> cm /FpI_<id> Do Q`). Both carry `/FormpdfItem`, a JSON text string with the item's parameters: kind, box (x, y, w, h in points from the top left), rotation in degrees clockwise on screen, flips, and for text the font (family, size, colour, line height) and paragraphs of runs (bold, italic, underline, strike, super and subscript, colour), for pictures the crop as fractions of the shown picture, its pixel size, EXIF orientation and format. Readers ignore the key; formpdf reads it back to edit the item, and re-editing rewrites only that item's form and stream. The placing stream is the source of truth; the copy on the form lets `items` recover an item when another tool merged the page's streams into one (pypdf's merge_page and compress do), in which case editing it removes its Do from the merged stream and places it again as its own stream.

The first item on a page wraps the existing content in a `q` stream before it and a `Q` stream after it (tagged `/FormpdfWrap`), because a page may leave its graphics state changed at the end. `/Contents` then reads: items at the back, the wrap's `q`, the page's own streams (with any in-place items between them), the wrap's `Q`, items at the front. Z-order is position in that array. Forward and backward swap with the next item; crossing the page's own content moves an item from front to back or the reverse.

Text is laid out by formpdf, not by a library: words are measured with reportlab's width tables for the font kit (fontkit.pick falls back to another family for characters a font lacks), broken greedily, a word longer than the line is broken by characters, and alignment, justify (extra space spread over the gaps of every line but the last), bulleted and numbered lists with a 1.6 em hanging indent and 1.5 em per level, super and subscript at 0.65 size raised 0.33 or lowered 0.12, and underline and strike lines follow. The baseline sits where CSS puts it for the same line height (half-leading plus ascent), so the window's editor and the page wrap and place lines the same way. Height grows with the text unless a height is given. The drawing is done on a reportlab canvas the size of the box and copied in as the item's form, so fonts are embedded as subsets with ToUnicode and the text extracts and searches.

Pictures are never re-encoded for geometry: a JPEG is embedded as is (DCTDecode, with the inverted Decode for Adobe CMYK), anything else becomes Flate with an SMask for transparency, and EXIF orientation becomes a matrix rather than new pixels. The form draws the picture through two matrices: orientation (the unit square mapped onto the shown picture) then scale and offset for the crop; the form's BBox clips what the crop leaves out. Changing only the crop, without a new box, keeps the picture's scale and moves the box so the remaining part stays where it was, in the item's rotated frame.

A picture already on the page (an image drawn by a top-level Do in the page's own content) is converted the first time it is changed: its Do is removed, the stream is split there, and an item that draws the same image object is inserted between the halves with `ctx` set to the graphics state's matrix at that point, so its placement is computed as the item's matrix times the inverse of `ctx`. It keeps its place in the stacking order and its clip. The box, rotation and flip come from that matrix. Several pictures converted in one call are done from the last to the first, so earlier indexes stay valid; `converted` maps "page:op" to the new ids. A move or rotation that leaves the size and content alone reuses the item's form instead of laying out and embedding the font again.

`edit_items` also reorders comments in a page's `/Annots` (`comments: [{page, index, to}]`). `GET /api/pdf/{id}/items/under` renders a page without one item (or one existing picture) for the window's editor to lay over the page while text is being edited. `GET /api/fonts/{file}` serves the engine's TrueType files, only those in the font folder, so the editor types in the same fonts the page will use. Redaction (Phase 3) must also strip the text kept in `/FormpdfItem`.

## 30. Redaction removes content instead of rasterizing · _v0.5.0 (services/pdf/redact.py apply, mark, _rewrite, _text_op, _clear_image, _verify, _render_check; services/pdf/edit.py redact; content/interp.py Glyph.tz)

`redact` now removes what is under each box and leaves the rest of the page as it was, still text. Areas come from the call plus every `/Redact` annotation in the file (each mark keeps its own `/IC` fill and `/OverlayText`); `mark_redactions` writes those annotations so a person or an agent can review the marks before anything goes. Per page, the content interpreter walks the page and its forms, and each stream is rewritten deepest form first. A glyph goes when its centre is inside a box or at least 40 percent of its box overlaps one; a `TJ` keeps its other glyphs and replaces each removed one by the displacement it advanced (`-(advance / tz) / size * 1000`), so nothing after it moves; `'` and `"` become their pre-operators plus a `TJ`. Images that touch a box are decoded, the covered pixels set to the fill, and the image re-encoded under a new name (`_rN`; DCT stays DCT, everything else Flate, soft masks kept), so the original stays only where another page still uses it. Inline images, paths and shadings wholly inside a box are dropped. A form that changed is copied under a new name rather than edited, because other pages may draw the same form. Marked-content spans that lost glyphs lose `/ActualText`, `/Alt` and `/E`. Resources are pruned to what the rewritten streams still draw.

Around the page's content, the boxes are clipped out with an even-odd clip of the page rectangle minus each box, so anything the interpreter could not attribute (a Type 3 glyph procedure, a pattern) does not paint there either. Comments overlapping a box go with their pop-ups and replies; widgets go and their fields are scrubbed from the AcroForm; page items whose box touches a box lose `/FormpdfItem`, so the old text does not survive in the JSON copy.

Two checks run before writing, and a failure stops the whole call with nothing written: the interpreter walks the rewritten page again and no non-space glyph may sit under a box and no image may touch one unless it is a cleared copy; then PDFium renders each page and the inside of every box must be one colour. Only then are the fill boxes and overlay text (Helvetica, sized to fit, white on dark fills) drawn on top, and orphaned objects removed. `mode: "raster"` keeps the old behaviour for scanned pages (entry 2) and now takes the fill colour.

## 31. Editing the text a PDF already has · _v0.6.0 (services/pdf/textedit.py detect, convert_many, walls; items.py layout, baseline, fit, _text_form, _norm_font, Page.render, change, read, render_without; content/interp.py Glyph.m and alpha; content/fonts.py WinAnsi bullets)

Text already on a page is edited by turning one paragraph into a page item (entry 29), the same model that made existing pictures editable: its glyphs leave the page's own content (each removed glyph becomes a TJ displacement of its advance, the redaction technique, so nothing else on the line moves) and an item with the paragraph's place, size, colour, alignment, line spacing and opacity takes its place, at the front of the page. Everything else in the page's streams is left as it was; only the base streams that held the paragraph's glyphs are rewritten.

Detection works on the interpreter's glyphs from the page's own content (not items, not forms). Each glyph carries its full text-rendering matrix (`m`) so the baseline direction, the effective size and the advance in user space come from the matrix, which handles rotated and scaled text. Glyphs that follow each other in stream order on one baseline become runs (a gap up to 1.5 em inside one text operator, 0.6 em across operators, because table cells and tab-separated labels are separate operators with wider gaps). Runs on one baseline join into lines when the gap is at most 0.6 em and no vertical rule from a path (`walls`) stands between them, which keeps table cells apart. A run that overlaps another with the same text is a duplicate (fake bold) and leaves with the line; invisible text (render mode 3, an earlier OCR layer) that overlaps a line by half its width leaves with it too. Lines join into a paragraph when the size is within 7 percent, the baseline gap is 0.9 to 1.75 em and steady within 15 percent of the first gap, the lines overlap, and the left edges agree within half an em or the right edges or centres within 0.3 em. Alignment is read from the edges (left, right, centre, or justify when three or more lines share both edges). A word broken by a hyphen at a line end is joined when the next line starts in lower case. A paragraph starting with a bullet becomes a bulleted item with its own hanging indent (`hang` in em). The key is the first glyph's op and sequence ("42.0"), valid for the version it was read from.

Fonts: the paragraph's main font is reused when it is embedded or a standard 14 font, is not Type 3, and can encode every character of the paragraph through its own reverse Unicode map; the item records it as `font.orig` and keeps the font object in its form's resources as `/FpO`. Layout then measures with that font's widths, takes its ascent and descent for the baseline, and draws those pieces with raw `Tj` operators appended to the form after reportlab's drawing; any piece the font cannot encode (a letter missing from a subset, or a style different from the original, such as bold added to a regular paragraph) falls back to the bundled family for that piece only, so a question mark is never drawn. Changing the family drops `orig`. Plain `text` replacing a converted paragraph keeps its bold, italic and alignment. A one-line left-aligned paragraph is marked `fit` and widens to its text up to the page margin instead of wrapping, as a heading would. Opacity from an ExtGState `ca` is kept through `/FpA gs` in the form.

Checked by converting every paragraph of page one of the corpus with no change and diffing PDFium renders: pages built with standard and embedded TrueType fonts come back pixel-identical or within a few hundred pixels; differences elsewhere come from kerning the source wrote with TJ (TeX), from fonts that cannot be reused (Type 3, CFF subsets whose letters have no Unicode), and from lines that are re-set with ordinary spaces. A conversion is a re-layout, so moving a paragraph also re-sets it.

The WinAnsi table maps the unused codes 127, 129, 141, 143, 144 and 157 to the bullet, as the PDF specification says readers should; reportlab and others write bullets there. reportlab pages cloned into forms can share resource objects (pypdf maps clones by reader id, which Python reuses), so `_text_form` copies the resource and font dictionaries before adding to them.

`edit_items` takes `{page, paragraph}` in update, arrange and remove; all paragraphs on a page are converted in one pass before any picture conversion, and picture ops are shifted by the operators a `'` or `"` expansion added. `items` lists `paragraphs` (leave out with `text: false`); `/items/under?paragraph=` renders the page without one. Updating a picture with `path` or `data` replaces it in its frame (width kept, height from the new aspect, centre kept).

## 32. Text recognition (OCR) · _v0.7.0 (services/pdf/ocr.py status, engine, run, _recognise, _skew, _level, _scan_only, _replace_scan, _layer, _placement, _image_dpi; core.py to_display; redact.py _render_check; requirements_ocr.txt; oc_install; freeze_backend)

The engine is RapidOCR with PaddleOCR's PP-OCRv6 small detection and recognition models (one multilingual model covers Latin scripts, Chinese and Japanese) and the mobile direction classifier, all Apache-2.0, run by onnxruntime on this computer. It is optional: `requirements_ocr.txt` is installed by `oc_install` unless `FORMPDF_NO_OCR=1`, and freezing collects it when present. The model files are looked up in `Formpdf/models/ocr` first (a person can drop newer files there) and then in the rapidocr package; their full paths are given to RapidOCR so it never tries to download, and `status()` reports a sentence for people when anything is missing, which capabilities, `get_context` and the window show. The dependency tree was vetted before adding it: opencv-python-headless and shapely bundle LGPL libraries (FFmpeg, GEOS) as separate shared objects, which the licence policy allows in distributed builds; everything else is permissive (NOTICE.md).

A page is skipped when formpdf already recognised it (its streams carry `/FormpdfOCR`; `redo` removes the old layer and recognises again) or, with `skip_text`, when it has at least twelve visible characters of real text. The page is rendered without annotations at the chosen resolution (default 300 dpi, 100 to 400) but never above the largest picture's own resolution with a floor of 150, because rendering a 200 dpi scan at 300 only slows recognition. Word boxes come back as quadrilaterals in the rendered bitmap.

Straightening: the median angle of lines wider than 40 pixels is the skew. Above 0.4 degrees the bitmap is turned back and recognised again. When the page is only a scan (one picture covering at least nine tenths of the page and no other content) the turned bitmap replaces the page's picture (JPEG at quality 85 if the scan was JPEG, Flate otherwise; grey when the scan has no colour), so the page itself is straight and the text lies flat on it. Otherwise the page is left alone and each line's words are set on the line's mean baseline, because extractors group words by baseline and tilted words come back scrambled.

The text layer is drawn with reportlab on a canvas the size of the page as shown, then placed as a form with a matrix that maps shown coordinates back to the page's own for each `/Rotate` (`_placement`), so rotated scans read correctly. Every word gets its own text matrix: the em height is the box height over the font's ascent to descent span, the horizontal scale fits the font's natural width to the box, the baseline sits above the box bottom by the descent, words less than five degrees off level are drawn level, and a space follows each word except the last on a line. Text is render mode 3 (invisible). The font is the engine's font kit (Inter, falling back to the other families for letters it lacks) embedded as a subset with ToUnicode, so accented and Greek or Cyrillic text extracts; letters no bundled family has are drawn with the closest font and may extract wrongly. The layer stream carries `/FormpdfOCR` so formpdf can find and replace it, and textedit ignores invisible text when it groups paragraphs.

Find, redaction, exports, reading mode and PowerPoint text boxes work on the recognised text because it is ordinary page text. Testing redaction on a rotated scan found that redaction's render check (entry 30) measured boxes in unrotated coordinates; `core.to_display` now maps a point to the page as shown for every rotation and the check uses it.

## 33. Connected scanners · _v0.7.0 (services/scan.py; routers/scan.py; routers/system.py NETWORK; main.py)

Three ways to reach a scanner, all without new dependencies. Network scanners speak eSCL (AirScan, Mopria), the HTTP protocol most scanners and multifunction printers sold in the last decade support on every platform: discovery sends one mDNS question for `_uscan._tcp` and `_uscans._tcp` from an ephemeral port with the unicast-response bit, collects answers for two seconds from private addresses only, and pairs PTR, SRV, TXT (`rs` resource path, `ty` model name) and A records with formpdf's own small DNS reader (name compression included), because the usual zeroconf library is LGPL and a browse is a few dozen lines. A person can also type an address. Every request goes through a proxy-less opener, only to private, link-local, loopback or `.local` hosts; anything else is refused with a sentence. Scanning reads `ScannerCapabilities` (glass, feeder, duplex, resolutions, colour), posts `ScanSettings` asking for JPEG, follows the job's `Location`, and reads `NextDocument` until the scanner answers 404, retrying on 503 while it warms up; the glass gives one page.

Scanners connected by USB go through the system's own driver stack when it is present: SANE's `scanimage` on Linux (eSCL devices SANE also lists are left out so they appear once) and WIA through PowerShell on Windows, with resolution and colour or grey set on the item and the feeder read until it is empty. macOS USB scanners that do not offer eSCL over USB are not reached; Image Capture has no command line.

`/api/scan/devices`, `/api/scan/capabilities` and `/api/scan/run` sit in their own router; a lock allows one scan at a time. A scan becomes a new PDF through `create.from_files` with pages fitted to the pictures, optionally made searchable by the OCR action, or is appended to the open PDF as a new version (OCR runs on the scanned pages only, before the merge). Preferences > Network lists text recognition and scanners as local.

## 34. Saving a signed PDF without breaking its signatures · _v0.8.0 (core.signed, writer, keep_pages, view_box, info; annot.annotate; edit.read_fields, fill_fields; routers/pdf.py _reprotect)

A signature covers the exact bytes of the file as it was signed, so anything that rewrites the file breaks it. When a PDF carries a signed signature field and is not encrypted, comments and form filling now save through `core.writer`: pypdf's incremental writer, which appends only the objects that changed. Two things in pypdf made it rewrite pages that were never touched, and both are undone here. Loading a page through the writer copies inherited attributes (Resources, MediaBox, Rotate) from the page tree onto the page, so `writer` removes keys the raw page object never had; and `view_box` used `page.cropbox`, which writes a /CropBox into a page that lacked one, so it now reads the raw entry. `keep_pages` then marks every page the operation did not touch as unchanged, so its object is not appended again. Flattening still writes a whole new file on purpose; a flattened PDF is a different document.

`read_fields` reports a signature field's value as `signed` or empty rather than the signature dictionary, so the window can hide the Sign here button on fields already signed. `_reprotect` leaves an output that is already encrypted alone: an incremental save of an encrypted original stays encrypted, and protecting it again would rewrite it.

## 35. Digital signatures · _v0.8.0 (services/pdf/sign.py; routers/identity.py; routers/system.py settings and NETWORK; actions.py batch; requirements, freeze scripts, formpdf_engine.py MODULES)

Certificate signing, validation and signing requests sit on pyHanko (MIT), which does PAdES signing, RFC 3161 timestamps and the incremental-update analysis; its dependencies are permissive, and certifi (MPL-2.0) is shipped unmodified. A digital ID is a PKCS#12 file in the data folder's `identities/`, with a small JSON beside it for the list. Make a digital ID creates a self-signed RSA-3072 certificate for signing (digital signature and non-repudiation key usage, email protection extended usage) and protects the key with the person's password, which formpdf never stores; it is trusted on this computer automatically. Import takes any .p12 or .pfx with its password. Trusted certificates are DER files in `trusted/`, named by their SHA-256 fingerprint, and are the only trust roots validation uses: no system store and no network fetch of revocation data, so a verdict never depends on the network.

`sign` signs into an empty signature field by name or into a box the person drew (a new field, named Signature, Signature2 and so on), optionally locks the form fields (FieldMDP all) and optionally certifies (DocMDP with forms, comments or no changes allowed). The visible appearance is a small PDF drawn with the font kit at the box's size: an optional picture on the left, then Digitally signed by, the date, and the reason and location when given, sized to fit. A timestamp is fetched only when the person has set a server in Preferences and asked for one; only the signature's hash goes to it.

Validation explains each signature in sentences. pyHanko checks the cryptography and the certificate path against the trusted folder; the change analysis is formpdf's own (`_changes`, `_later`), because pyHanko's diff policy rejects annotation changes it cannot explain and called a commented PDF invalid. Each later revision is compared with the one before it: new or changed annotations are comments, field values are form filling, a new signature is signing, anything else in a page or the catalogue is other changes. A certification signature's DocMDP level then decides whether those changes were allowed; a plain signature reports what happened after it and stays valid as long as what it covers is unchanged. The verdict is valid, unknown (cryptography intact but the certificate is not trusted here) or invalid. `revision` hands back the bytes a signature covers, which is the signed version a person can save.

Signing requests: `request_signatures` assigns the PDF's empty signature fields to the signers in document order (the person places them first with Prepare form, where they control the position), puts the signer's name in each field's tooltip (Signature 1 of 2: name), and records the people, their emails and the message under `/FormpdfRequest` in the catalogue. The status reads which fields are signed and names who is next. No server is involved; the person sends the PDF by email and brings the signed copy back, and `join_copy` accepts it only when it is this PDF with more signatures (same first revision, more signed fields), so an older or unrelated file is refused. Signing and request preparation are left out of batch, which has no place for an ID password per file.

## 36. Accessibility: tags, checker, fixes and tag editing · _v0.9.0 (services/pdf/access.py; actions.py batch)

`autotag` builds a PDF/UA-style structure tree from what formpdf already knows about a page. `layout.page_blocks` (the same reader behind Reading mode and Word export) gives headings, paragraphs, list items, tables and pictures in reading order (xycut); pdfplumber's table finder gives each cell's box; `layout.running` finds headers, footers and page numbers repeated across pages. The content interpreter then says which operator painted each glyph and picture. Each glyph votes for the block or cell that contains its centre (or the nearest within one and a half text sizes); an operator belongs to the block with most votes, and an operator whose glyphs fall in no block becomes its own paragraph at the end of the page, so no text is lost from the tags. Pictures become Figures with a Layout BBox; tiny pictures and a full-page scan under OCR text are background; paths and shadings are background; running headers and footers are Pagination artifacts.

The page's content streams are then rewritten one by one, keeping each stream's dictionary so formpdf's page items and OCR layers stay recognisable: a marked-content sequence opens before the first operator of a new owner and closes at the next owner change, before BT, ET, q and Q, and at the end of each stream, so sequences never straddle a text object or a graphics state and never begin inside a path (path construction takes the owner of the painting operator that ends it). Existing marked content is dropped except optional content (layers); a form XObject is tagged as one unit through its Do. Headings are renumbered across the document so the first level used is H1 and no level is skipped. Lists become L, LI and LBody; tables become Table, TR, TH (first row, Scope Column) and TD; links become Link elements inside the paragraph they cover, fields Form elements placed by position, and other comments Annot elements, each with an OBJR, a StructParent and a ParentTree entry. The catalogue gets MarkInfo, Lang (the setting or the spelling language), a title (the current one, else the first heading) shown in the window title, and pages with annotations get Tabs S. Tagging a signed PDF is refused because it rewrites every page. Renders before and after are pixel-identical on the scratch corpus, and Poppler's `pdfinfo -struct-text` reads the tree.

`accessibility` runs Acrobat's 32 checks in its seven groups, each passed, failed, manual or skipped (structure rules are skipped without tags), with page findings and the element id where one applies. Tagged content counts glyphs, pictures and paths that are neither in a marked-content sequence with an MCID nor an artifact, with content inside a form inheriting the mark of the Do that draws it. Character encoding counts glyphs with no Unicode mapping. Scripts, flicker and timed responses become manual only when the PDF has JavaScript or multimedia. Titles such as untitled or document count as missing.

`fix_accessibility` repairs what can be repaired without guessing content: tags (when there are none), title and DisplayDocTitle, language, tab order, annotations and fields missing from the tags (added as OBJR elements with new ParentTree keys, appended to the Document element), field descriptions (the label to the left of the field or just above it, else the field name made readable), table summaries (columns, rows and header text) and bookmarks from the heading tags. Alternate text is never invented. `structure` lists regions (the first non-grouping elements in tree order, so Sect and Div are walked through) with page, order on the page, type, text from their MCIDs and a box from the content they mark; ids are index paths from the tree root, stable between a reader and a writer clone. `edit_structure` retags, sets alternate text, moves a region before or after its element sibling, or makes it decorative: its MCIDs are rewritten to Artifact sequences in the page streams, their ParentTree slots set to null and the element removed. `accessibility_report` writes the check as a small standalone HTML page. edit_structure is left out of batch because its ids belong to one file.

## 37. Print layouts and grayscale · _v0.10.0 (services/pdf/printing.py; services/pdf/colour.py)

Imposition is geometry first: `plan` turns the chosen pages (each as its displayed size after /Rotate) and the options into sheets, each a list of cells with a clip rectangle and a matrix. `print_layout` returns that plan in top-left coordinates for the window's preview, so the preview never needs a PDF; `print_pdf` builds the same plan into a new PDF. ## 40. Action lists · _v0.11.0 (services/lists.py; routers/lists.py)

## 46. PowerPoint export rebuilds objects · _v0.12.0 (services/pdf/objects.py; services/pdf/slides.py to_pptx; routers/mcp.py to_pptx result)

## 50. Threaded text frames and the font report · _v0.15.0 (services/pdf/items.py layout pi and wi, split_story, _runs_of, _page_keys, change frames_of, store, flow, thread, unthread, to_page, grow; services/pdf/fontreport.py report, installed)

A thread is a set of text items sharing a `thread` id, ordered by `seq`. The story (paras and font) is stored only on the first frame; followers store an empty paragraph and are rendered with their share. Storing the whole story once means an edit through any frame cannot fork the text, and reading the PDF back recovers the story without stitching frames together. layout now returns, per line, the paragraph index and the word index the line starts at (None for a line that starts inside a word broken by characters); split_story lays the remaining story out at each frame's width, takes as many lines as the height holds, moves the cut back past mid-word lines and the very first line, and rebuilds the two halves of the cut paragraph from its words. The first half is marked split so justification still applies to its last line; the second half is marked cont so it has no list marker and does not advance the numbering. Lines are counted, not measured, so a frame holds floor(height / line height) lines.

Everything that touches a thread (an update of any frame, thread, unthread, removal, a move) only marks the thread; each marked thread is laid out once at the end of change(), after every other request, so a request that edits the story and moves frames renders each frame once. Frames are found by scanning each page's content streams for the thread id in the item key without building a Page, because Page() normalises /Contents and /Resources and would rewrite every page of the file. grow inserts a blank page of the last frame's size directly after it (not at the end, so the story stays together) and places a copy of the last frame there, repeating until the story fits, at most 200 frames. Turning grow on for a lone box makes it a one-frame thread and, when the box was auto-height, first clamps it to 36 pt above the page's bottom edge, because an auto-height box never overflows. A thread reduced to one frame without grow becomes an ordinary auto-height box again. Pages grown for a story are not removed when the story shrinks; the empty frames stay.

Moving an item to another page (update to_page) removes it from its page and writes it on the other with the same parameters; a picture carries its image object across. Before this, a move across pages was refused.

The font report reads fonts from every page and form resource through pdfa.fonts and pdfa.embedded, strips subset prefixes, and compares normalised names (lower case, letters and digits, MT and PS suffixes dropped) with the names fc-list reports and the font files in the platform folders, both cached for the engine's life. ## 52. Editing existing shapes and page boxes · _v0.17.0 (services/pdf/paths.py _layout, _start, _paths, read, change, _gstate, _color; services/pdf/boxes.py describe, read, change)

## 83. What the outside validator found · _v0.40.0 (services/pdf/pdfa.py alternates_to_rgb, _rgb_fn, add_colorants, _missing_colorants, ua_extension, _set_meta; access.py _link_text, _xmp_title, claim_ua)

## 84. Right-to-left text in the order it is drawn · _v0.41.0 (services/pdf/access.py Marks.drawn, reading_text, visual_rtl, rtl_order rule, rtl fix, leftward spacing; layout.py reading_line; core.py _rtl_lines)

Whether right-to-left text reaches a screen reader the right way round depends on the order the page draws its glyphs, not on how it looks, so the check follows each element's glyphs in drawing order: steps that go right mean visual order, steps that go left mean reading order. Counting over the element rather than per marked-content id matters because some files give each glyph its own id. Visual order is a failure only without ActualText on the element or above it, and the fix writes the same text formpdf's tagger writes, built from the glyph positions by the one function the layout reader uses, which keeps neighbouring Latin words and numbers in their own order. The same function fixed the text action: pdfium orders the letters inside each right-to-left run but not the runs, so every Hebrew or Arabic line came back word-reversed in either drawing order.

## 85. Changes applied in InDesign · _v0.41.0 (docs/indesign/apply-formpdf-changes.jsx locate, key, plan, tidy, run)

The change list was always meant for the layout app, and InDesign's scripting reaches the stories directly, so the script applies changes in the text rather than placing them on the page. The words around a change are the only anchor that survives reflow, so matching compares a key that drops spaces, line breaks and hyphens, which is also what absorbs a word hyphenated at a line end in the PDF; context decides between repeats and refuses when it cannot. Every position is worked out on the unedited stories and the edits are made from the end backwards, which keeps the positions valid without searching again. ## 88. A PDF's own font served to the editor · _v0.43.0 (services/pdf/webfont.py; routers/pdf.py doc_webfont)

The engine already writes edited text back in the PDF's embedded font when the font has the letters (font.orig), but the window drew the editor in Inter, so what a person typed did not look like what was saved. GET /api/pdf/{id}/webfont?page&name finds the font by its name in the page's resources and every Form XObject under them (so formpdf's own FsItem text resolves too), and rebuilds the embedded program as a font a browser accepts: TrueType and OpenType get a new Unicode cmap, bare CFF (Type1C and CID-keyed CIDFontType0C) is wrapped into an OpenType font with FontBuilder. The Unicode map comes from FontInfo.reverse, and each character's glyph is found the way the PDF finds it: Differences names, the (3,0) symbol cmap at F000 plus the code, a Unicode cmap, the CFF built-in encoding, CIDToGIDMap for Type0, the Adobe glyph list last. Advance widths are taken from the PDF's /Widths, not the program, because the page and the engine's layout both use those, so the editor wraps where the saved text will. The name table is replaced (embedded subsets often carry none, and Chromium's sanitizer rejects a font without one); OS/2 and post are added when missing. Type1 (FontFile) and Type3 return 404 and the window keeps the kit family. Results are cached per working copy, which never changes under its id.

## 89. Bookmarks edited in place · _v0.46.0 (services/pdf/outline.py edit_outline; actions.py batch list)

edit_outline takes ops (add, rename, delete, dest, up, down, indent, outdent) addressed by the bookmark's position in the list core._outline gives the window: a pre-order walk that counts only titled items, so the index the person clicked is the node the engine changes. Each op relinks the existing outline items through /First, /Last, /Next, /Prev and /Parent by hand instead of rebuilding the outline, so a bookmark's own destination, action, colour, style and open state survive every op but the one that changes them; pypdf's TreeObject helpers were not used because they work on copies of the item dictionaries and would leave the real tree unlinked. /Count is recomputed for the whole tree after the ops, keeping each item's open or closed state (negative counts stay negative). A new bookmark points at the whole page (/Fit); dest replaces the item's /A as well, because a reader prefers /A. An outline root is created when the PDF has none. The action is not offered in Batch, where an index into one file's outline means nothing.

## 90. Squiggly, polygon, polyline and cloud annotations · _v0.47.0 (services/pdf/annot.py POLY, cloud_r, cloud_arcs, squiggle, draw, _annot, comments; services/pdf/xfdf.py; routers/mcp.py)

normalize takes points for the POLY kinds (3 or more for polygon and cloud, 2 for polyline, capped at 2000). draw strokes polygon and polyline as paths (fill only on the closed ones) and the cloud as one cubic bezier bump per segment of about 2r along each edge, offset outward along the normal chosen from the shoelace sign so the bumps face out for clockwise and counter-clockwise input; bbox grows by r so the bumps are not clipped. The dictionary gets /Vertices in user space, /BS, /IC when filled, and for the cloud /BE <</S /C /I 1>> plus /IT /PolygonCloud, the two ways readers recognise a cloud (ISO 32000-2 12.5.4 and 12.5.6.9). Squiggly is a fourth MARKUP kind with /QuadPoints; its appearance is a zigzag under each rect whose amplitude scales with the line height (0.6 to 2.4 pt). comments() reports a /Polygon with either cloud marker as kind cloud. XFDF import reads polygon (style cloudy gives cloud), polyline vertices and interior-color, and squiggly coords.

## 91. Callout annotations · _v0.48.0 (services/pdf/annot.py callout_leg, normalize, bbox, draw, _annot, comments; services/pdf/xfdf.py intent, callout, fringe, style)

A callout is a /FreeText with /IT /FreeTextCallout (ISO 32000-2 12.5.6.6): /CL holds the leader as three points (tip, knee, end) in user space, /LE /OpenArrow puts the arrow at the tip, and /RD says how far the box sits inside /Rect, which must also cover the leader; readers use /RD to find the text box, so it is computed from the same box the appearance draws. The kind takes the box like freetext plus anchor (or points[0]) and defaults to a 1 pt border in red. callout_leg leaves the box from the middle of the side facing the tip (the side whose distance beyond the box is larger) and bends at most 18 pt out, so short leaders stay straight-ish. The appearance draws the leader and arrow in page space before _upright turns the box, so text in a box on a rotated page stays upright while the leader keeps its true angle. comments() reports FreeText with the callout intent or a /CL as callout. XFDF export now carries intent, callout, fringe and style cloudy for every annotation that has them, and import reads them back, both on the native path (the dictionary keeps /IT, /CL, /RD, /BE) and the window path (the box is the rect minus the fringe, the anchor is the first callout point).
